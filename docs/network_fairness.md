# Current network fairness and correctness

Traditional is the repository's blocking POSIX server, with one detached pthread per accepted connection. accept runs on the main thread; workers loop over recv and retry partial send, EINTR, EOF and connection errors. MSG_NOSIGNAL suppresses SIGPIPE. SIGINT/SIGTERM closes the listener, shuts down active sockets and waits for workers to drain. Resource exhaustion fails the server rather than silently reducing concurrency. Maximum server slots: 4096; runner allows up to 1000 connections.

The pinned io_uring server is retained with tracked correctness fixes in network/patches/io_uring.patch: partial sends retain the buffer and offset, error/EOF only returns a selected buffer, send errors close the socket, SIGPIPE is suppressed, SQ acquisition and submit/wait are checked. It retains single-shot accept, a 2048-entry SQ and 4096 x 2048-byte provided buffers. ENOBUFS or submission failure aborts measurement. There is no SQPOLL or zero-copy claim. Termination uses process teardown (kernel closes descriptors/ring); it does not promise application-level draining of pending echoes. The runner stops it after the client finishes.

Both listen on IPv4 wildcard, backlog 512, SO_REUSEADDR, use 2048-byte receive chunks and leave TCP_NODELAY off. Socket send/receive sizes use host defaults. The Traditional per-connection stack buffer differs from the io_uring provided-buffer pool. io_uring can batch across completions; Traditional schedules separate blocking workers. These architectural differences are the experiment, and prevent syscall-only explanations.

The pinned Rust client is reused with a tracked patch for TCP read_exact, verified payloads, bounded socket/connect waits, explicit TCP_NODELAY=false, setup handshake, barrier and common monotonic deadline. Setup is excluded, late responses do not count, and each worker must complete a measured response. Active connections means established, handshake-verified client sockets, not a guarantee all workers are simultaneously scheduled or all sockets always have an outstanding request. A setup/I/O/payload failure or worker panic fails the run. There is no sustained network warmup or CPU affinity/isolation; default levels are1/100 and 1000 is conditional on target validation.

The runner uses pipefail and an external timeout; failed clients do not append successful CSV rows. Both implementations must pass smoke tests at a connection level before using that level. Check host fd/thread/cgroup limits, CPU contention and memory at 1000. No throughput conclusion is valid from a failed or degraded active connection count.

See legacy_network_audit.md for the original epoll/io_uring/client audit and historical measurements; those describe a separate methodology, not current source.

Diagnostic server /proc snapshots bracket the whole client process, including handshake/setup and drain. PROFILE=1 adds client /usr/bin/time -v data. Neither substitutes for measurement-window pidstat/perf evidence. In the WSL audit the 1000-connection one-second test failed due to zero-response workers; it is not valid throughput. See benchmark_audit.md for findings and how to test client/CPU/TCP bottleneck hypotheses without assuming the answer.
