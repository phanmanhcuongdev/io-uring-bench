# Measurement protocol: traditional-v2

The current implementation and command reference is README.md. The detailed evidence, conditions and exact official Linux commands are in benchmark_audit.md. Superseded traditional-v1 and original legacy results never enter default charts.

1. Verify Linux/kernel/fio/liburing, target filesystem/device, regular non-sparse input file and memory availability. Keep power policy, VM allocation, host load and background activity stable. DEVICE is only a label. No raw-device benchmark or cache-dropping operation occurs.
2. Cached QD1 uses sequential buffered 4 KiB reads over 256 MiB, explicitly prewarmed before each method, invalidate=0. Confirm residency/absence of memory pressure on the target; otherwise this is buffered sequential reading, not a proven memory-only workload. Ramp is excluded from fio throughput.
3. Random Direct QD1: 4 KiB over 1 GiB, direct=1, 1 job x depth1 on both. Random Direct QD32: same distribution/range, psync 32 jobs x depth1 versus io_uring 1 x depth32. Both random workloads set norandommap=1/randrepeat=1 for uniform sampling with replacement. Exact sequences and CPU/thread footprints differ; achieved depth must be checked, not assumed.
4. Sequential Direct is now QD1: 128 KiB over 1 GiB, one stream on each side. The overlapping-stream QD32 design was removed. Device caching and repeated range traversal remain; direct bypasses page cache, not device cache. This workload says nothing about queued sequential QD32 performance.
5. All disk jobs use thread=1, time_based=1, group_reporting=0. Runner supplies engine, numjobs, iodepth, offset=0, runtime and ramp; no fio workload overrides them. Sum per-job bandwidth/IOPS exactly once, and weight completion latency by total_ios. Jobs have nearly equal time-based measurement intervals; inspect runtime/start skew before interpreting aggregate bandwidth on a severely overloaded host. Do not sum an aggregate group together with its constituent workers.
6. Execute adjacent method pairs, reverse method order each repetition, preserve scenario order. This balances first/second position over ten repeats but does not remove device-cache carry-over, fixed scenario order, thermal drift or correlated observations. Inspect per-run data/CV; collect longer sessions on target hardware if unstable. Do not cherry-pick individual repeats.
7. Network is shared-host TCP loopback, shared Rust blocking thread-per-connection client, no pipelining. Both servers have 2048-byte chunks, backlog512, SO_REUSEADDR, default socket buffers, TCP_NODELAY=false. Same duration/message size and same profile setting within a session. Default levels1/100; 1000 is conditional.
8. Every client worker connects, validates one full echo handshake, then waits at a barrier. Main sets a common Instant-based start/deadline before release. Count only writes/responses completed before deadline; read_exact and payload validation include late draining but its responses do not count. Any setup/I/O/payload failure or worker with zero measured responses fails the entire client. Collection time is logged separately. Handshake excludes startup, but is not a sustained network warmup; barrier release and CPU scheduling remain in the application-level measurement.
9. status.txt starts running, becomes complete only at successful runner end, and records failed exit for normal error/signal paths. SIGKILL can leave running; analyzers reject it. Metadata declares expected scenarios/connections/repeats. Fail closed on selected invalid/failed/incomplete sessions; do not silently discard failed runs to retain a success chart. Select --device explicitly. Never combine differing sessions/machines into one group.
10. Export per-run data, mean/median/sample stddev/CV and mean/median percentage differences. SVG uses median and requires >=10 matched positive unique IDs; sample stddev zero for one smoke repeat means no spread estimate, not stability. These are descriptive statistics, not confidence intervals or proof of significance. Report practical effect versus variability and session drift; paired per-repeat values can be examined for uncertainty without treating short repeats as independent by default.

Official commands use 30-second disk runs plus 5-second ramp, and 15-second network windows. Runner defaults remain 8/2 seconds for disk and 8 seconds for network; override explicitly for the official protocol. No official suite was run during audit. All v2 pairs require fresh measurements. Preserve every raw historical/failed/smoke session and use explicitly selected labels/output directories.
